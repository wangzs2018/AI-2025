# 学生成绩管理系统开发指南

## 1. 项目概述
一个前后端分离的成绩管理平台，支持学生信息、课程信息、成绩录入与统计分析、权限控制及审计。前端使用 Vue3 + TypeScript，后端使用 Java (Spring Boot) 构建 RESTful API，持久化采用关系型数据库（MySQL/PostgreSQL），并实现分页、筛选、导出、权限角色与操作日志。

## 2. 目标与核心价值
- 高效的成绩录入与批量导入导出（Excel/CSV）。
- 准确的成绩统计与报表（平均分、最高/最低、分布、绩点、排名）。
- 审计与追溯（谁在什么时间修改了哪条成绩）。
- 角色权限隔离（管理员/教师/教务/学生）。
- 稳定扩展：后续可增加绩点计算、学业预警、可视化图表、家长门户。

## 3. 用户角色与权限边界
| 角色 | 主要操作 | 说明 |
|------|---------|------|
| 管理员 | 用户/角色管理、系统设置、导入导出、审计查看 | 全局最高权限 |
| 教师 | 成绩录入、成绩修改（限本人授课课程）、班级成绩统计 | 不可管理系统用户 |
| 教务 | 课程计划维护、学期管理、成绩复核 | 不直接修改单条成绩（仅发起复核流程） |
| 学生 | 查看个人成绩、绩点、排名、课程平均分趋势 | 无写权限 |
| 家长(可选) | 查看所关联学生的汇总 | 需与学生账号绑定 |

## 4. 技术栈选择
### 前端
- Vue 3 + TypeScript + Vite
- Vue Router + Pinia (状态管理)
- UI 组件库：Element Plus / Ant Design Vue（二选一）
- Axios 封装统一请求/拦截器/错误处理
- ECharts 或 Chart.js (成绩分布与趋势图)
- XLSX.js (前端导入预校验，可选)

### 后端
- Java 17 （与长期支持版本对齐，便于后续升级）
- Spring Boot 2.5.12 + Spring Web + Spring Data JPA / MyBatis
- Spring Security / Sa-Token (权限与认证) + JWT
- Lombok / MapStruct (减少样板代码与对象转换)
- MySQL 或 PostgreSQL（推荐 PostgreSQL）
- Redis (缓存课程/学生基本信息、排行榜、Token 黑名单)
- Flyway / Liquibase (数据库版本迁移)
- OpenAPI 3 (springdoc-openapi) 自动生成接口文档
- Logback + ELK (后续日志集中化) / 简单本地文件日志初始阶段

## 5. 系统总体架构
分层结构：
- 前端：`/src` 按领域模块划分（students, courses, grades, reports, auth）。
- 后端：Hexagonal / 分层架构：controller → service → domain(model + repository接口) → infrastructure(repository实现, external integrations)。
- API 交互：REST + JSON，分页与筛选标准化参数。未来可扩展 GraphQL。
- 权限：基于角色 + 细粒度方法/资源权限注解。

## 6. 模块划分与功能清单
### 基础数据模块
- 学生管理：增删改查、批量导入、状态（在读/休学/退学）。
- 课程管理：课程信息、学分、开课学期、授课教师关联。
- 教师管理：基本信息与授课课程列表。

### 成绩模块
- 成绩录入：单条录入、批量上传模板（Excel）。
- 成绩修改：权限控制 + 审批（可选流程：教师提交→教务复核→生效）。
- 成绩查询：按学生、课程、班级、学期过滤。
- 成绩统计：
  - 课程统计：平均分、最高/最低、分布直方图。
  - 学生统计：学期平均分、绩点、排名、趋势图。
  - 排名：班级/年级排名计算（缓存与定时刷新）。

### 报表模块
- 导出：Excel/CSV 按条件筛选导出成绩。
- 导入：标准模板上传→前端/后端校验→入库事务控制。
- 图表：分布、趋势、绩点雷达图。

### 权限与认证模块
- 登录 / 刷新 Token。
- 角色与菜单权限（前端路由守卫 + 后端注解）。
- 操作日志与审计（后端 AOP 记录修改前后数据差异）。

### 辅助模块
- 通知（成绩发布/复核结果）邮件或站内消息。
- 系统设置（学期维护、绩点规则公式）。

## 8. API 设计范式
统一前缀：`/api/v1`
- 学生：GET /students?query=&page=&size=  POST /students  PUT /students/{id}  DELETE /students/{id}  POST /students/import  GET /students/{id}
- 课程：GET /courses  POST /courses  ...
- 成绩：GET /grades?studentId=&courseId=&term=  POST /grades  PUT /grades/{id}  POST /grades/import  GET /grades/stat/course/{courseId}  GET /grades/stat/student/{studentId}
- 认证：POST /auth/login  POST /auth/refresh  POST /auth/logout
- 报表：GET /reports/export?type=grades&filters=...
错误返回结构：
```json
{ "timestamp": "2025-11-08T10:00:00Z", "path": "/api/v1/grades", "error": "VALIDATION_ERROR", "message": "score_raw must be between 0 and 100" }
```
分页统一：`{ "items": [...], "page":1, "size":20, "total": 123 }`

## 13. 安全与合规要点
- 密码：BCrypt 哈希 + 最低长度要求。
- Token：短生命周期 + Refresh Token + 黑名单（Redis）。
- 输入校验：后端 Bean Validation + 前端表单校验双层。
- 防护：CSRF（JWT + SameSite=Strict），XSS（前端编码 + 后端过滤），SQL 注入（ORM / 预编译）。
- 审计：关键变更记录前后数据快照。
- 数据备份：定期全量 + 增量，策略与恢复演练。

## 17. 衍生与新增需求说明
基于上述输入，系统需新增以下设计点：
- 多租户/多校区：需在关键表增加 `tenant_id`、`campus_id` 字段；权限隔离查询需自动带过滤条件。
- 审批流程：引入成绩变更工作流表与状态枚举（DRAFT, SUBMITTED, REVIEWING, APPROVED, REJECTED）。
- 自助注册：开放学生注册 API + 邮箱/手机号唯一校验；管理员审核（可选）。
- 主题切换：前端通过 CSS Variables + Pinia 存储主题名，提供至少 `default`、`dark`、`high-contrast`。
- Rate Limit：基于 Redis 实现滑动窗口或令牌桶；按 IP + 用户 ID + 接口权重。返回 `429 TOO MANY REQUESTS`。
- WebSocket：建立 `/ws/grades` 通道，推送成绩审批结果与发布通知，前端自动刷新列表。
- 数据备份策略：需定义脚本与执行频率（每日增量，每周全量）。
- 多租户隔离策略：初期采用同库逻辑隔离（discriminator），后续可升级至 schema per tenant。

## 19. 审批流程设计
状态流转：
`DRAFT -> SUBMITTED -> REVIEWING -> (APPROVED | REJECTED)`
规则：
1. 教师录入或修改成绩生成 DRAFT。
2. 提交后进入 SUBMITTED，触发通知给教务角色。
3. 教务打开审批任务进入 REVIEWING，期间成绩不可再次编辑。
4. 审批通过：状态 APPROVED，写入正式成绩表 `score_final`；失败 REJECTED 回退并产生通知。
5. 审批全程写入审计日志与版本号（version 递增）。

## 20. WebSocket 设计概述
通道：`/ws/grades`（成成绩 / 审批）、`/ws/notifications`（系统通知）。
鉴权：握手阶段验证 JWT；订阅时携带租户与校园标识过滤。
消息格式：
```json
{ "type":"GRADE_APPROVAL", "payload": { "gradeId":123, "status":"APPROVED", "version":2 } }
```
断线重连：前端心跳 + 指数退避重连。

## 21. 主题切换实现要点
1. 维护 `themes.css` 中多套变量：`--color-bg`, `--color-text`, `--color-primary`。
2. Pinia `themeStore` 保存当前主题；持久化 localStorage。
3. 切换时动态替换 `<html data-theme="dark">` 属性或注入样式。
4. 提供公共组件 `ThemeSwitcher.vue`。

## 22. Rate Limiting 设计
算法：滑动窗口计数或令牌桶（初期滑动窗口即可）。
维度：IP + 用户ID + 接口路径。
配置：默认窗口 60 秒；教师角色 200 次/窗口，学生 300 次/窗口（查询多），管理端敏感操作 50 次/窗口。
超限响应：HTTP 429 + `Retry-After` 头。
监控：定期扫描 `rate_limit_log` 数据做可视化。

## 23. 非功能需求初稿
性能：单接口 P95 < 300ms；批量导入 1 万条 < 2 分钟；WebSocket 推送延迟 < 2 秒。
可用性：MVP 阶段单节点；后期目标 99.5% 可用性。
扩展性：多租户数量增长时可拆分库；通知模块可替换为消息队列（Kafka）。
安全：所有写操作需鉴权与审计；速率限制与 IP 黑名单。

## 24. 风险与缓解
1. 多租户数据串扰风险 → 全局查询增加租户过滤 + 单测覆盖。
2. 审批流程复杂度上升 → 明确状态机 + 单元测试状态迁移。
3. 排名统计性能瓶颈 → 异步计算 + 缓存 + 分页排名。
4. Rate Limit Redis 单点 → 后期启用 Redis Cluster。
5. WebSocket 连接过多 → 后期使用消息代理 + 网关分发。

## 28. API 文档与契约管理（springdoc-openapi + Knife4j）
### 28.1 目标
为前后端提供统一、可交互、版本化的接口契约平台，支持：
- 自动生成 OpenAPI 3 规范 JSON & YAML
- 可视化调试（Knife4j UI）
- 多分组（基础数据 / 成绩 / 审批 / 报表 / 系统）
- 版本与变更追踪（语义化版本号 + Changelog）
- 导出离线文档（Markdown / HTML / PDF）

### 28.2 集成步骤（待后端骨架建立后执行）
1. 依赖（pom.xml）：
  - `org.springdoc:springdoc-openapi-starter-webmvc-ui`
  - `com.github.xiaoymin:knife4j-openapi3-spring-boot-starter`
2. 基础配置类 `OpenApiConfig`：
  - 定义 `@Bean OpenAPI`（title, description, version, license, contact）
  - 定义分组：使用 `GroupedOpenApi` 按包路径：
    - `group = basic-data` (student, course, teacher)
    - `group = grade` (grade, ranking)
    - `group = approval` (grade_approval)
    - `group = report` (report, export)
    - `group = system` (auth, tenant, campus, notification)
3. 安全方案：
  - 在 OpenAPI 中添加 `HTTP bearer JWT` securityScheme
  - `@SecurityRequirement(name = "BearerAuth")` 标注需要授权的控制器/方法
4. Knife4j UI：
  - 默认访问：`/doc.html` 或 `/knife4j`（视版本）
  - 开发环境开启增强文档，生产可通过配置开关关闭（`knife4j.enable=false`）
5. OpenAPI 资源：
  - JSON: `/v3/api-docs`
  - 分组：`/v3/api-docs/{group}`
  - YAML: `/v3/api-docs.yaml`
6. 版本策略：
  - 使用语义化版本：`MAJOR.MINOR.PATCH` 对应「破坏性 / 新增向后兼容 / 修复」
  - 在文档首页加入 `CHANGELOG` 链接（版本历史）
7. 变更治理：
  - 破坏性修改需保留旧接口（Deprecated 标记）至少 2 个小版本
  - 新增字段向后兼容（保证前端 JSON 解析健壮）
8. 导出 & 合规：
  - 引入脚本（后续生成）自动拉取 `/v3/api-docs` 保存为 `openapi-vX.Y.Z.json`
  - 可选：使用 `openapi-generator` 生成 TS API 客户端（位于 `frontend/src/api/generated`）

### 28.3 控制器注释规范
| 注释目标 | 规范 |
|----------|------|
| 类注释 | @Tag(name="学生管理", description="学生 CRUD 与导入") |
| 方法摘要 | @Operation(summary="创建学生", description="新增单个学生并返回ID") |
| 参数说明 | @Parameter(description="学生主键ID", example="1001") |
| 返回体 | 使用响应 DTO 并在类上加 @Schema(description=...) |
| 分页返回 | 统一封装 PageResponse<T> 并加泛型 Schema | 

### 28.4 示例配置（示意）
```java
@Configuration
public class OpenApiConfig {
   @Bean
   public OpenAPI baseOpenAPI() {
      return new OpenAPI()
        .info(new Info()
           .title("学生成绩管理系统 API")
           .version("0.1.0")
           .description("MVP 阶段接口说明。破坏性修改将提前公告。")
        )
        .addSecurityItem(new SecurityRequirement().addList("BearerAuth"))
        .components(new Components().addSecuritySchemes("BearerAuth",
           new SecurityScheme().name("Authorization").type(SecurityScheme.Type.HTTP).scheme("bearer").bearerFormat("JWT")));
   }
   @Bean
   public GroupedOpenApi basicDataGroup() { return GroupedOpenApi.builder().group("basic-data").packagesToScan("com.example.gradeapp.student","com.example.gradeapp.course","com.example.gradeapp.teacher").build(); }
}
```
